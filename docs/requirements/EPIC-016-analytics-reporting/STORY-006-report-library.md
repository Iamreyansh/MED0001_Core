## Overview

The Report Library story provides a centralized admin-facing system for generating, scheduling, and downloading platform-wide reports. It supports both on-demand generation and scheduled reports (daily, weekly, monthly) delivered via email to configured recipients. Reports are categorized as Finance, Operations, Compliance, and Growth. Large reports are generated asynchronously as background jobs, and their status is trackable via a job polling endpoint. All report downloads link to AWS S3 pre-signed URLs that expire after 7 days. The compliance report category is retained for 5 years to meet regulatory requirements.

|------|--------|
| admin_super | Full access to all reports |
| admin_finance | Generate and schedule Finance reports |
| admin_operations | Generate and schedule Operations and Growth reports |
| admin_compliance | Generate and schedule Compliance reports |
| admin_support | Read report history only |
| pharmacy_owner | No access (use STORY-004 report catalogue) |

## Business Rules

1. **Async Threshold**: Reports generating more than 10,000 rows are always processed as async background jobs. Reports with ? 10,000 rows may be returned inline (synchronous) when the `async=false` query param is set.
2. **Download URL Expiry**: Report download links (AWS S3 pre-signed URLs) expire after 7 days from generation. After expiry, the report file is NOT deleted from S3 (retained for compliance); a new pre-signed URL can be generated by re-fetching the history entry.
3. **Scheduled Reports**: Scheduled reports run at the configured cadence (DAILY at 06:00 IST, WEEKLY on Monday 06:00 IST, MONTHLY on the 1st at 06:00 IST). They are emailed to `email_recipients` as attachments (PDF or CSV depending on format setting).
4. **Compliance Retention**: Reports in the `COMPLIANCE` category are retained in S3 for a minimum of 5 years. All other categories are retained for 2 years.
5. **Role-Based Access**: `admin_finance` can only generate/schedule `FINANCE` category reports. `admin_operations` handles `OPERATIONS` and `GROWTH`. `admin_compliance` handles `COMPLIANCE`. `admin_super` can access all.
6. **Audit Logging**: Every report generation (on-demand or scheduled) creates an immutable audit log entry with: `report_id`, `generated_by` (user or `SCHEDULER`), `period`, `row_count`, `generated_at`, `download_url`.
7. **Schedule Toggle**: When a scheduled report is enabled/disabled via PATCH, the change takes effect at the next scheduled run. The current in-progress run (if any) is not affected.
8. **GSTR-8 Report**: The `TAX_GSTR8_PREP` report aggregates TCS (Tax Collected at Source) data for marketplace operators. This report is specifically relevant to Namma MedMate as a marketplace and must be accurate to 0 Rs tolerance.
9. **Schedule H Register**: The `COMPLIANCE_SCHEDULE_H` report lists all prescription-required medicine sales with customer PAN/Aadhaar reference for Drug Inspector audit. Available for download at any time for the last 5 years.
10. **Job Expiry**: Async report generation jobs expire after 24 hours if not completed. An expired job returns `status: FAILED` with `error_message: JOB_TIMEOUT`.

### POST /api/v1/admin/reports/:report_id/generate

Trigger on-demand report generation.

**Auth**: Bearer JWT - `admin_super`, `admin_finance`, `admin_operations`, `admin_compliance`

**Path Parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| report_id | string | Report identifier from library |

**Request Body**
```json
{
  "period_from": "2026-07-01",
  "period_to": "2026-07-31",
  "filters": {
    "zone_id": "uuid-zone-1",
    "pharmacy_id": null
  },
  "format": "CSV",
  "async": true
}
```

**Response 202 (Async)**
```json
{
  "success": true,
  "data": {
    "job_id": "uuid-job-1",
    "report_id": "GMV_COMMISSION_PAYOUTS",
    "status": "QUEUED",
    "estimated_rows": 15420,
    "queued_at": "2026-07-24T01:30:00Z"
  },
  "meta": {}
}
```

**Response 200 (Synchronous for small reports)**
```json
{
  "success": true,
  "data": {
    "report_id": "COHORT_RETENTION",
    "status": "COMPLETED",
    "download_url": "https://s3.amazonaws.com/namma-medmate-reports/cohort_20260724.csv?X-Amz-Expires=604800",
    "row_count": 156,
    "generated_at": "2026-07-24T01:30:02Z",
    "expires_at": "2026-07-31T01:30:02Z"
  },
  "meta": {}
}
```

**Error Table**

| HTTP Code | Error Code | Condition |
|-----------|-----------|-----------|
| 404 | REPORT_NOT_FOUND | report_id does not exist |
| 403 | FORBIDDEN | Role cannot generate this report category |
| 422 | INVALID_PERIOD_RANGE | period_from > period_to |
| 429 | TOO_MANY_JOBS | More than 5 active jobs for this user |

## Acceptance Criteria

1. **AC-001**: POST /generate with `async: true` for a report with > 10,000 rows returns HTTP 202 with a `job_id`.
2. **AC-002**: GET /jobs/:job_id for a COMPLETED job returns a non-null `download_url` and `expires_at` 7 days in the future.
3. **AC-003**: PATCH /schedule with `enabled: true` and empty `email_recipients` returns `422 MISSING_RECIPIENTS`.
4. **AC-004**: A `admin_finance` user attempting to generate a `COMPLIANCE` report receives `403 FORBIDDEN`.
5. **AC-005**: GET /history shows `generated_by: "SCHEDULER"` for scheduled report runs.
6. **AC-006**: `COMPLIANCE` category reports appear in GET /history even after 2 years (5-year retention).
7. **AC-007**: `TAX_GSTR8_PREP` report row totals reconcile with commission ledger totals for the same period (zero tolerance).
8. **AC-008**: Async job that runs beyond 24 hours is marked `FAILED` with `error_message: JOB_TIMEOUT`.
9. **AC-009**: All report generation events (manual and scheduled) appear in the audit log with actor, timestamp, and row count.

## Notes

- The 14 named reports in the story specification are defined as seed data in `admin_report_definitions` table populated during platform initialization.
- Report formats: CSV for tabular data, PDF for formatted compliance registers. Some reports support both; the `format` param in generate selects the output.
- Future: Self-service report builder where admins can define custom SQL-based reports. The library infrastructure is designed to support this via `report_query_template` column addition.
