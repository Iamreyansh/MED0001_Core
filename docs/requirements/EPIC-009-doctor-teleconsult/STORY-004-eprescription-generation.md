## Overview

This story defines the issuance, storage, and linkage of digital e-prescriptions generated by Namma MedMate's in-house teleconsult doctors. After completing a consultation call, the assigned doctor issues an e-prescription via the admin interface. The e-prescription contains a digitally signed medicines list with dosage, frequency, and quantity, plus a unique RX-ID and a doctor digital signature hash for authenticity. e-Prescriptions are automatically stored in the patient's prescription wallet, and in cart-mode consults, they are automatically linked to the relevant cart. The story also supports advice-only consultations (no medicines) with a formal consult receipt, PDF download for the patient, and the technical linkage between e-Rx and the Rx quote broadcast flow.

## Business Rules

1. **Doctor assignment gate:** A doctor can only issue an e-prescription for the specific consult that was assigned to them. The `consult_id` in the issuance request must match a consult with `doctor_id = authenticated_doctor_admin`. Cross-consult issuance returns `CONSULT_NOT_ASSIGNED`.
2. **Digital signature hash:** The `digital_signature_hash` is computed as `SHA256(doctor_id + "|" + patient_name + "|" + medicines_json_canonical + "|" + issued_at_iso8601)`. This hash is stored on the e-Rx and re-verified on each read. Any tampering with the record changes the hash, making forgery detectable.
3. **Auto-link to cart (cart-mode):** When the consult has `is_cart_mode: true` and a valid `cart_id`, the issued e-prescription is automatically attached to the cart (`cart.prescription_id = e_rx_id`) immediately on issuance. No separate `link-to-cart` call is needed in cart-mode.
4. **RX-ID format:** `RX-{YYYYMMDD}-{pharmacy_prefix}-{6-digit-seq}` - globally unique, human-readable, and suitable for inclusion on the physical/PDF prescription. For teleconsult (no pharmacy at issuance time), pharmacy_prefix = `NMM` (Namma MedMate).
5. **90-day validity:** e-Prescriptions expire 90 days after `issued_at`. Expired e-prescriptions cannot be attached to a new cart but remain visible in the patient's prescription history.
6. **Advice-only flow:** When `advice_only: true` is set, `medicines` is empty and `advice_text` is required (max 1000 chars). The e-Rx is stored with `type: E_PRESCRIPTION` and `is_advice_only: true`. It still generates a consult receipt PDF.
7. **Auto-populate Rx quote broadcast:** If the patient's cart contains Rx-only items and the e-Rx is linked, the medicines list from the e-Rx pre-fills the Rx quote broadcast payload when the patient initiates a quote request (EPIC-010 STORY-003).
8. **Prescription wallet storage:** On issuance, the e-prescription is created as a `Prescription` record (EPIC-008 STORY-001) with `type: E_PRESCRIPTION`, `source: TELECONSULT`, `status: VERIFIED`, and `is_verified: true`. The `teleconsult_id` foreign key links the two records.

## API Endpoints

### 1. Issue e-Prescription (Doctor/Admin Action)

```POST /api/v1/admin/consults/:consult_id/eprescription```

**Authentication:** Bearer JWT - `admin_super` | `admin_operations`
**Rate Limit:** 10 req/min

**Request Body:**
```json
{
  "medicines": [
    {
      "name": "Metformin 500mg",
      "dosage": "500mg",
      "frequency": "1-0-1 (morning and night)",
      "quantity": 60,
      "unit": "tablets",
      "duration_days": 30,
      "notes": "Take with food"
    },
    {
      "name": "Glipizide 5mg",
      "dosage": "5mg",
      "frequency": "0-1-0 (before lunch)",
      "quantity": 30,
      "unit": "tablets",
      "duration_days": 30,
      "notes": "Take 30 minutes before meals"
    }
  ],
  "advice_only": false,
  "advice_text": null,
  "clinical_notes": "Patient presents with T2DM. HbA1c > 8.5. Starting dual therapy."
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `medicines` | array | If `advice_only=false` | List of prescribed medicines |
| `medicines[].name` | string | Yes | Medicine name as to be dispensed |
| `medicines[].dosage` | string | Yes | Dosage (e.g. "500mg") |
| `medicines[].frequency` | string | Yes | Dosing schedule (e.g. "1-0-1") |
| `medicines[].quantity` | integer | Yes | Total quantity to dispense |
| `medicines[].unit` | string | Yes | `tablets`, `capsules`, `ml`, `sachets` |
| `medicines[].duration_days` | integer | No | Prescription duration in days |
| `medicines[].notes` | string | No | Medicine-specific instructions |
| `advice_only` | boolean | Yes | If true, prescription has no medicines |
| `advice_text` | string | If advice_only=true | Clinical advice text (max 1000 chars) |
| `clinical_notes` | string | No | Internal doctor notes (not on patient PDF) |

**Response `201 Created`:**
```json
{
  "success": true,
  "data": {
    "prescription_id": "rx_01J3KP7VLLL222",
    "rx_id": "RX-20260724-NMM-000451",
    "rx_type": "E_PRESCRIPTION",
    "consult_id": "consult_01J3KP7VKKK111",
    "doctor": {
      "id": "tdoc_01J3KP7VXYZ123",

      "qualification": "MBBS MD",
      "registration_no": "DL98765"
    },
    "patient_name": "Ravi Kumar",
    "issued_at": "2026-07-24T10:40:00Z",
    "is_verified": true,
    "seal": "VERIFIED",
    "advice_only": false,
    "medicines": [
      {
        "name": "Metformin 500mg",
        "dosage": "500mg",
        "frequency": "1-0-1 (morning and night)",
        "quantity": 60,
        "unit": "tablets",
        "duration_days": 30,
        "notes": "Take with food"
      }
    ],
    "advice_text": null,
    "digital_signature_hash": "a3f8d9c1e2b4...",
    "expires_at": "2026-10-22T10:40:00Z",
    "cart_linked": true,
    "cart_id": "cart_01J3KP7VGHJ000",
    "download_url": "/api/v1/prescriptions/eprescriptions/rx_01J3KP7VLLL222/download"
```

**Errors:**

| Code | HTTP | Description |
|------|------|-------------|
| `CONSULT_NOT_FOUND` | 404 | Consult ID not found |
| `CONSULT_NOT_ASSIGNED` | 403 | Consult is not assigned to this doctor |
| `CONSULT_ALREADY_HAS_EPRESCRIPTION` | 409 | e-Rx already issued for this consult |
| `ADVICE_TEXT_REQUIRED` | 422 | `advice_only=true` but `advice_text` is blank |
| `MEDICINES_REQUIRED` | 422 | `advice_only=false` but `medicines` is empty |
| `CONSULT_NOT_COMPLETED` | 422 | Consult must be in IN_CALL or COMPLETED state |

### 3. Link e-Prescription to Cart (Manual)

```POST /api/v1/prescriptions/eprescriptions/:id/link-to-cart```

**Authentication:** Bearer JWT - `customer`
**Rate Limit:** 10 req/min

*Used when the consult was NOT in cart-mode but the customer wants to attach the resulting e-Rx to an active cart.*

**Request Body:**
```json
{
  "cart_id": "cart_01J3KP7VGHJ000"
}
```

**Response `200 OK`:**
```json
{
  "success": true,
  "data": {
    "prescription_id": "rx_01J3KP7VLLL222",
    "cart_id": "cart_01J3KP7VGHJ000",
    "cart_prescription_id": "rx_01J3KP7VLLL222",
    "message": "e-Prescription linked to cart successfully"
  }
}
```

**Errors:**

| Code | HTTP | Description |
|------|------|-------------|
| `PRESCRIPTION_NOT_FOUND` | 404 | e-Rx not found for this customer |
| `PRESCRIPTION_EXPIRED` | 422 | e-Rx has expired |
| `CART_NOT_FOUND` | 404 | Cart not found or not active |

## Data Models

### EPrescription (extension of Prescription)

The e-prescription is stored as a `Prescription` record with `type = E_PRESCRIPTION` plus the following additional fields:

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `rx_id` | string | UNIQUE, NOT NULL | Human-readable RX-ID (RX-YYYYMMDD-NMM-XXXXXX) |
| `teleconsult_id` | UUID | FK ? consults.id, NOT NULL | Source consultation |
| `doctor_id` | UUID | FK ? teleconsult_doctors.id, NOT NULL | Issuing doctor |
| `medicines` | JSONB | nullable | Array of prescribed medicine objects |
| `is_advice_only` | boolean | default false | No medicines prescribed |
| `advice_text` | text | nullable | Clinical advice text |
| `clinical_notes` | text | nullable | Internal notes (not on PDF) |
| `digital_signature_hash` | string(64) | NOT NULL | SHA256 hash for tamper detection |
| `is_verified` | boolean | NOT NULL, default true | Always true for e-prescriptions |
| `seal` | string | NOT NULL, default `VERIFIED` | Verification seal |
| `pdf_s3_key` | string | nullable | S3 key for generated PDF |
| `pdf_generated_at` | timestamp | nullable | When PDF was generated |

### MedicinePrescribed (JSONB array element schema)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Medicine name |
| `dosage` | string | Yes | e.g., "500mg", "10mg" |
| `frequency` | string | Yes | e.g., "1-0-1", "BD", "TDS" |
| `quantity` | integer | Yes | Total quantity dispensed |
| `unit` | string | Yes | `tablets`, `capsules`, `ml`, `sachets` |
| `duration_days` | integer | No | Duration of therapy |
| `notes` | string | No | Patient instructions |

## Acceptance Criteria

- [ ] **Given** a doctor issues an e-prescription for a cart-mode consult, **when** the e-Rx is created, **then** the cart's `prescription_id` is automatically updated to the new e-Rx ID without any additional API call.
- [ ] **Given** an admin attempts to issue an e-prescription for a consult not assigned to them, **when** the request is submitted, **then** the API returns HTTP 403 with `CONSULT_NOT_ASSIGNED`.
- [ ] **Given** an e-prescription is issued with `advice_only: true` and no `advice_text`, **when** the request is submitted, **then** the API returns HTTP 422 with `ADVICE_TEXT_REQUIRED`.
- [ ] **Given** an e-prescription is issued, **when** the issuance succeeds, **then** a `Prescription` record is created with `type: E_PRESCRIPTION`, `status: VERIFIED`, `source: TELECONSULT`, and `expires_at = issued_at + 90 days`.
- [ ] **Given** an e-prescription is issued with two medicines, **when** the `digital_signature_hash` is computed, **then** it equals `SHA256(doctor_id + "|" + patient_name + "|" + canonical_medicines_json + "|" + issued_at)` and is verifiable on read.
- [ ] **Given** a customer calls `GET /api/v1/prescriptions/eprescriptions/:id` for their e-Rx, **when** the response is received, **then** `signature_valid: true` and the `seal: "VERIFIED"` badge is present.
- [ ] **Given** a second e-prescription issuance is attempted on the same consult, **when** the request is submitted, **then** the API returns HTTP 409 with `CONSULT_ALREADY_HAS_EPRESCRIPTION`.
- [ ] **Given** an e-prescription is older than 90 days, **when** a customer attempts to link it to a cart, **then** the API returns HTTP 422 with `PRESCRIPTION_EXPIRED`.
- [ ] **Given** a customer calls the download endpoint, **when** the PDF has not yet been generated, **then** the system generates the PDF on demand and redirects to the signed S3 URL.
- [ ] **Given** the e-Rx medicines list pre-fills the Rx quote broadcast (EPIC-010), **when** the broadcast is initiated for a cart with a linked e-Rx, **then** the broadcast payload includes all medicines from the e-Rx's `medicines` array.

## Notes

- `medicines_json_canonical` for hash computation = `JSON.stringify(medicines.sort_by_name())` with keys in alphabetical order and no whitespace. Canonical form is documented in the platform crypto spec.
- PDF template must include: Namma MedMate header + logo, RX-ID, doctor name/qualification/registration, patient name, date, medicines table, advice text, `VERIFIED` digital seal, and validity period.
- For advice-only e-Rx, the PDF header reads "Consultation Receipt" rather than "e-Prescription."
- `pdf_s3_key` is `eprescriptions/{rx_id}.pdf`. PDF is generated asynchronously after issuance and the download endpoint redirects immediately if already generated; triggers on-demand generation if not yet available.
