## Overview

Feature Adoption Metering tracks how pharmacy subscribers actually use each ERP module, giving Admin HQ visibility into which features are driving value and which are underutilised. Usage events are tracked transparently via API middleware - every authenticated call to the pharmacy ERP dashboard increments the relevant module's event counter for that account. Admins can view platform-wide adoption percentages, drill into per-module per-account usage, enable or disable individual modules for specific accounts (overriding plan-level defaults), and send nudge campaigns to accounts that are on the right plan but haven't activated a module.

## Business Rules

1. **Event tracking via middleware** - every ERP API call (to pharmacy dashboard endpoints) is intercepted by a middleware that records a usage event for the corresponding module and account; no explicit event-push endpoint is required from clients.
2. **Adoption percentage** - `adoption_pct = (accounts_using_module / accounts_eligible_for_module_by_plan) - 100`; eligibility is determined by the module matrix.
3. **Low adoption threshold** - a module is flagged as "low adoption" when `adoption_pct < 20%`.
4. **Event count reset** - module event counts reset on the first day of each calendar month; monthly data is archived.
5. **Module enable/disable override** - admin can enable a module for an account even if their plan doesn't include it (e.g. for beta access), or disable a module that the plan includes (e.g. compliance hold). These overrides supersede plan-level access.
6. **Seat usage** - `seat_usage = count of active (non-expired, non-deactivated) pharmacy_staff users on the account`.
7. **Invoice usage** - `invoice_usage = count of invoices generated by the account in the current calendar month` via the ERP billing module.
8. **Adoption score** - per-account `adoption_score = (modules_used_in_30d / modules_eligible) - 100` rounded to the nearest integer.
9. **Nudge targeting** - nudges are sent only to accounts that are on a plan that includes the module AND have event count = 0 in the last 30 days for that module.
10. **Feature adoption sync** - platform-wide adoption metrics are aggregated nightly; per-account last_active_at is updated in real time.

## API Endpoints

### 1. Feature Adoption Overview (Admin)

```
GET /api/v1/admin/crm/modules
Authorization: Bearer JWT (admin_super | admin_operations | admin_finance)
```

**Query Parameters**

| Parameter | Type   | Description                                    |
| --------- | ------ | ---------------------------------------------- |
| `group`   | string | Filter by module group (CORE, ANALYTICS, etc.) |
| `tier`    | string | Filter by plan tier                            |
| `sort`    | string | `adoption_pct`, `accounts_using`, `module`     |
| `order`   | string | `asc` or `desc`                                |

**Response 200**


## Data Model

### ModuleUsageEvent (aggregated)

| Field            | Type                                   | Constraints       | Description          |
| ---------------- | -------------------------------------- | ----------------- | -------------------- |
| `id`             | UUID v4                                | PK                | Record identifier    |
| `account_id`     | UUID                                   | FK ? crm_accounts | Account              |
| `module_id`      | VARCHAR(50)                            | NOT NULL          | Module code          |
| `event_month`    | DATE                                   | NOT NULL          | First day of month   |
| `event_count`    | INTEGER                                | DEFAULT 0         | Events in month      |
| `last_active_at` | TIMESTAMPTZ                            | NULLABLE          | Last event timestamp |
| UNIQUE           | `(account_id, module_id, event_month)` |                   | Composite unique     |

### AccountModuleOverride

| Field        | Type                      | Constraints       | Description                         |
| ------------ | ------------------------- | ----------------- | ----------------------------------- |
| `id`         | UUID v4                   | PK                | Override record                     |
| `account_id` | UUID                      | FK ? crm_accounts | Account                             |
| `module_id`  | VARCHAR(50)               | NOT NULL          | Module code                         |
| `enabled`    | BOOLEAN                   | NOT NULL          | Override flag                       |
| `reason`     | TEXT                      | NOT NULL          | Mandatory reason                    |
| `toggled_by` | UUID                      | FK ? admin_users  | Admin who toggled                   |
| `toggled_at` | TIMESTAMPTZ               | DEFAULT NOW()     | Toggle timestamp                    |
| UNIQUE       | `(account_id, module_id)` |                   | One override per module per account |

## Acceptance Criteria

1. Adoption overview lists all 18 modules with correct `adoption_pct` = `accounts_using / accounts_eligible - 100`.
2. Modules with `adoption_pct < 20%` are flagged in the overview (e.g. via a `low_adoption: true` flag).
3. Admin toggles Advanced Analytics ON for an account not on RETAIL_PRO; module is accessible in that account's ERP.
4. After module toggle, `AccountModuleOverride` record exists with `override = true` and the reason.
5. Nudge endpoint sends emails to all accounts on RETAIL_PRO with 0 Advanced Analytics events in last 30 days.
6. `adoption_score` for an account using 5 of 8 eligible modules = `FLOOR(5/8 - 100) = 62`.
7. Event counts reset to 0 on the first day of each month; previous month is archived.
8. `seat_usage.used` correctly counts only active (non-deactivated) staff users.
9. `invoice_usage.used` correctly counts invoices generated in the current calendar month via ERP billing.
10. Module detail shows `eligible_not_using` accounts sorted by account name.

## Notes

- Event tracking middleware should be lightweight (async write to a queue, not inline DB write) to avoid latency on ERP API responses.
- Module event counts are aggregated monthly; raw events are not stored long-term.
- "Eligible-but-not-using" list in module detail is the primary outreach target for CSMs and nudge campaigns.
